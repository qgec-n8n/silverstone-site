# Service Route Design Briefs

## Web Design & Development

- Commercial objective: move a buyer from “the site looks/works wrong” to a discovery call about commercial decision paths.
- Buyer emotional state: frustrated by a polished surface that still fails to explain value or capture demand.
- Visual metaphor: premium browser and publishing system, with the site as an operating surface.
- Section architecture: approved editorial copy, conversion cards, Conversion Path Lens, benchmark evidence, process rail, reserved browser-window demos.
- Route-specific components: Conversion Path Lens and two reserved live-website frames.
- Image plan: `general-services-1` as illustrative capture/conversion panel, captioned as conceptual.
- Icon plan: pencil/ruler, workflow, gauge and integration icons.
- Animation plan: image clip reveal, conversion cards in depth, benchmark spring emphasis, browser frames entering as reserved objects.
- Mobile simplification: one-column editorial, stacked metrics, static browser frames.
- Reduced-motion plan: no transform-dependent comprehension; copy, frames and metrics remain visible.

## App Development

- Commercial objective: qualify app ideas around the smallest useful workflow and first-release decision.
- Buyer emotional state: excited but unsure whether the idea is too broad, too costly or under-specified.
- Visual metaphor: product-state stack, release states and data integration.
- Section architecture: approved editorial copy, product capability cards, Product State Stack, benchmarks, release process rail, deterministic state-map module.
- Route-specific components: Product State Stack and synthetic first-release state panel.
- Image plan: `services_data_integration` as systems/data architecture image.
- Icon plan: plug, workflow, shield and progress icons.
- Animation plan: state-stack assembly, alternating process rail movement, cards entering as product states.
- Mobile simplification: keep stack above cards; deterministic module becomes a single stable panel.
- Reduced-motion plan: reveal by opacity with all state labels present.

## AI Voice Agents

- Commercial objective: frame voice agents as governed workflows requiring scripts, state, actions and handoff.
- Buyer emotional state: curious about automation but concerned about callers, errors and trust.
- Visual metaphor: telephony oscilloscope, waveform, transcript and call-state machine.
- Section architecture: approved editorial copy, voice capability cards, Call Flow Oscilloscope, benchmark evidence, process rail, ElevenLabs-ready call/transcript reserved surfaces.
- Route-specific components: Call Flow Oscilloscope plus two required reserved placeholders.
- Image plan: `services_lead_followup` as conversational follow-up panel.
- Icon plan: phone, headset, shield and workflow icons.
- Animation plan: waveform-like signature motion, reserved panels entering as controlled call states.
- Mobile simplification: transcript/call placeholders stack with fixed height.
- Reduced-motion plan: waveform information remains static and labelled.

## AI Receptionists

- Commercial objective: show front-desk automation as routing, booking and human handoff rather than generic answering.
- Buyer emotional state: wants fewer missed enquiries but fears bad customer experience.
- Visual metaphor: multi-channel reception console converging into named destinations.
- Section architecture: approved editorial copy, receptionist cards, Front Desk Convergence, benchmarks, process rail, chat and ElevenLabs reserved surfaces.
- Route-specific components: Front Desk Convergence and two required reserved placeholders.
- Image plan: `general-services-1` as enquiry-capture panel.
- Icon plan: headset, calendar, shield and workflow icons.
- Animation plan: channel convergence, reserved surfaces with controlled window bars.
- Mobile simplification: one channel per row, handoff copy stays visible.
- Reduced-motion plan: no channel motion required for understanding.

## Content Creation

- Commercial objective: move buyers from “produce more content” to a governed source-led editorial system.
- Buyer emotional state: overloaded by publishing demands and wary of low-quality AI output.
- Visual metaphor: editorial loom and source-to-channel atomisation.
- Section architecture: approved editorial copy, content cards, Editorial Loom, benchmarks, process rail, deterministic atomisation module.
- Route-specific components: Editorial Loom and synthetic content atomisation panel.
- Image plan: `general-services-2a` as modular editorial package panel.
- Icon plan: sparkles only for source transformation, plus shield/check controls.
- Animation plan: loom assembly, channel cards revealing as governed outputs.
- Mobile simplification: channel outputs stack below the source narrative.
- Reduced-motion plan: all channel labels remain visible without sequencing.

## AI Automation

- Commercial objective: position automation as an operating layer with approvals, exceptions and observability.
- Buyer emotional state: sees manual friction but worries about hidden errors or uncontrolled actions.
- Visual metaphor: process lattice and exception-aware control surface.
- Section architecture: approved editorial copy, automation cards, Process Lattice, benchmarks, process rail, deterministic workflow control module.
- Route-specific components: Process Lattice and synthetic workflow control surface.
- Image plan: `services_workflow_automation` as workflow/reporting panel.
- Icon plan: workflow, zap, shield and plug icons.
- Animation plan: lattice assembly, exception-path emphasis, metric spring emphasis.
- Mobile simplification: reduce lattice density and keep exception copy adjacent.
- Reduced-motion plan: exception path labelled rather than movement-dependent.

## AI & Automation Consulting

- Commercial objective: sell clarity before implementation: prioritise, govern, buy/build/defer or leave alone.
- Buyer emotional state: ambitious but uncertain which opportunity deserves investment.
- Visual metaphor: opportunity matrix and advisory instrument.
- Section architecture: approved editorial copy, advisory cards, Opportunity Matrix, benchmarks, process rail, deterministic advisory module.
- Route-specific components: Opportunity Matrix, distinct from the automation Process Lattice.
- Image plan: `services_consulting` as readiness/audit panel.
- Icon plan: search, gauge, shield and arrow icons.
- Animation plan: matrix cells assemble as decision criteria, process rail enters as advisory sequence.
- Mobile simplification: matrix becomes two-by-two then single column on narrow screens if needed.
- Reduced-motion plan: matrix remains static and labelled.
