## Messaging rule

Explain the business problem before the technology. Prefer plain verbs: answer, route, book, connect, publish, update and review. Avoid “revolutionary”, “superpowers”, “best”, “guaranteed”, “effortless” and unsupported outcome figures.

### Objections

**“We are not technical.”**  
You do not need to choose the architecture. Bring the business problem, current process and systems; the technical options can be translated into practical decisions.

**“We already use several tools.”**  
The first question is whether they can be configured or connected more effectively. A new platform is not the default answer.

**“We do not want automation to frustrate customers.”**  
The scope should define what the system may answer, what it must ask and when a person takes over.

**“We are not ready for a large project.”**  
Start with one useful workflow or page journey and an agreed review point.
