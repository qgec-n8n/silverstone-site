# Repo → UI Map (What controls what)

This map is used to prevent guessing and reduce scope drift. It calls out the *actual* sources of truth for the UI areas in Requested Edits 1–8.

---

## Global build pipeline

- Source CSS: `src/css/**`
- Built CSS: `assets/css/styles.css` (generated by `node build-css.js`)
- Source JS: `src/js/**`
- Built JS bundle: `assets/js/app.js` (generated by `node scripts/build-js.js`)

Always rebuild after source edits:
- `bash scripts/codex.requested-edits.sh`

## Hero shader section (Edit 1 + Edit 7)

### Markup pattern (multiple pages)
- `<section class="hero title-band ...">`
- `.hero-media` contains `#hero-shader-canvas`
- `.content` contains:
  - `h1`
  - hero subheading `p` (grey on mobile currently)
  - `.cta-buttons` (if present)

### Styling source of truth
- `src/css/components/hero.css`

### What to change
- Edit 1 (desktop-only): style `.hero.title-band .content` to become a tight container on desktop.
- Edit 7 (mobile-only): hide the hero `p` text on mobile **without shifting layout**.

### Concrete selectors + scope hooks
- Desktop container: `@media (min-width: 769px)` + `.hero.title-band .content`
- Subheading text: `.hero.title-band .content p` (the grey subtitle)
- CTAs (for container sizing context): `.hero .cta-buttons`

## About page: Silverstone_22 + Silverstone_28 service-row images (Edit 2)

### Markup
- `about.html` service rows contain:
  - `assets/images/zip/Silverstone_28.jpg` with `class="img-cover-center"`
  - `assets/images/zip/Silverstone_22.jpg` with `class="img-cover-center"`

### Why cover-fill can fail
- `src/css/components/cards.css` contains rules for `.service-image.neon-card img` that enforce `object-fit: contain` and can override the `img-cover-center` intent due to specificity.

### Where to fix
- Prefer a **desktop-only** override in `src/css/pages/about.css` scoped to `.page-about` and `img.img-cover-center` inside the service-row image card.

### Concrete selectors + scope hooks
- Wrapper card: `.page-about .service-row .service-image.neon-card`
- Image: `.page-about .service-row .service-image.neon-card img.img-cover-center`
- Desktop-only scope: `@media (min-width: 769px)`

## Services page: General_Services cards (Edits 3 + 4)

### Markup
- `services.html` includes `<picture>` blocks for:
  - `General_Services_1`
  - `General_Services_2A`
  - `General_Services_2B`
  - `General_Services_3`

These images contain baked-in overlay copy; image compression directly affects text crispness.

### Desktop pixelation source (Edit 3)
- Desktop `<source type="image/webp" media="(min-width: 769px)">` currently selects `.webp` on desktop browsers.
- Fix requires desktop choosing `.jpeg` for these four images (keep mobile webp).

### Mobile landscape card source (Edit 4)
- `src/css/pages/services.css` contains aspect-ratio/object-fit rules that can force a landscape frame even when the mobile images are portrait.
- Fix should be mobile-only and scoped to only the General_Services cards using an HTML class hook (`general-services-card`).

### Concrete selectors + scope hooks
- General Services wrapper (add class in HTML): `.service-image.neon-card.general-services-card`
- Image inside wrapper: `.page-services .general-services-card img.service-img.img-cover-center`
- Mobile-only scope: `@media (max-width: 768px)`

## Services: Innovation Gallery Neural Grid (Edits 5 + 6)

### Important: runtime JS injection
- The Services grid is populated by JS at runtime:
  - `src/js/gallery.js` defines `CURATED_IMAGES`
  - It clears `#neural-grid` and injects tiles

So image replacement must be done in:
- `src/js/gallery.js` (not only in fallback HTML)

### Replacement rules
- Replace all square/landscape legacy filenames containing `1-1` and `3-2` with allowed `services_*` assets.
- Replace all portrait legacy filenames containing `2-3` with `*_#_Mobile.jpeg` assets with varied prefixes.

### Concrete selectors + scope hooks
- Source list: `src/js/gallery.js` → `CURATED_IMAGES` entries (`type: 'square' | 'landscape' | 'portrait'`)
- Grid target: `#neural-grid` (runtime injected; HTML fallback not authoritative)

- `codex/ASSET_REPLACEMENT_MATRIX.md`

## Index targeted subtitle sentences (Edit 8)

### Markup
- `index.html` contains the two target sentences inside `p.section-subtitle` elements:
  - under `#what-we-automate`
  - under `#pricing`

### Existing styling interaction
- Home page sections set `--color-silver` to white, which can make subtitles white.
- The fix must be **targeted**: add a class (e.g., `subtitle-muted`) to only those two paragraphs and set its color to `--color-silver-original`.

Where to implement CSS:
- `src/css/base/layout.css` or `src/css/pages/home.css` (either is acceptable if scoped and includes proof marker).
