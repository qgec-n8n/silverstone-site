Responsibility architecture

Automation, agent and human — drawn explicitly

Automation

Deterministic steps with fixed rules — move data, format it, file it, notify the right place.

Agent

A bounded assistant that drafts or suggests inside guardrails, never acting without a checkpoint.

Human

The approver for anything sensitive, ambiguous or irreversible. The exception always ends here.

Exception-aware workflow run

Choose a queue and a sensitivity rule. The demo runs a synthetic batch through the lattice, auto-handling the routine items and stopping the flagged one for manual approval.

    What this demonstrates — and what it does not

    Demonstrates

    • Routine items handled automatically along one path
    • A single flagged exception held for human approval
    • An auditable event log for every step

    Does not

    • Act autonomously or take any irreversible action
    • Use real records, accounts or live integrations
    • Replace the human approval step it routes to

    Static fallback: a batch enters intake, routine items pass through sort and action to done, and any item matching the rule is diverted upward to a human approval node before it can continue.

    Fit

    Where this is — and isn't — the right call

    • The work repeats and the rules can be written down
    • You want speed on the routine and a person on the exception
    • You value an audit trail over a black box
    No unbounded autonomy. We do not deploy agents that act without limits. Sensitive, ambiguous or irreversible steps always pause for a named human to approve — and any workflow can be stopped by its owner at any time.
