How scope becomes price

Price starts with a clearly defined scope.

We do not publish a one-size figure, because honest pricing follows the work. This page explains the variables that move a price and the phases an engagement runs through. Any numbers shown are illustrative, not a quote.

Five variables

What moves a price

Open each variable to see how it changes the explanation. This explainer changes text only — it never calculates a quote.

Complexity

A single well-defined flow costs less than many interacting ones. The more decisions, states and edge cases involved, the more design and testing the work needs.

Systems involved

Connecting to one tool you already control is simpler than coordinating several systems with different owners, permissions and reliability.

Risk

Higher-impact or regulated work needs more review, stronger safeguards and a clearer boundary — which adds to the effort, and is worth it.

Content & data readiness

If approved answers, content and clean data already exist, we move faster. If they need to be gathered or cleaned first, that becomes part of the scope.

Support

A one-off build differs from an ongoing, monitored service. The level of monitoring, response and iteration you want shapes the running cost.

Questions

Pricing questions

Why aren't there fixed prices?

Because the same headline goal can mean very different work. A fixed figure would either over-charge the simple cases or under-deliver the complex ones. We price the scope we agree.

How do I get an actual figure?

Start with a discovery call. Once we have agreed a problem and a smallest useful step, we can give you a real, written scope and cost.

Can we start small?

Yes — that is our default. We would rather prove a first release than commit you to a large programme up front.
